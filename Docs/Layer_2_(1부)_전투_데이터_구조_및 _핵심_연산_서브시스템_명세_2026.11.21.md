# Layer 2 (1부): 전투 데이터 구조 및 핵심 연산 서브시스템 명세 2026.11.21

Layer 2는 `UWorldSubsystem` 생명주기를 기반으로 서버 권한(Server Authority) 하에 전투 공식, 속성 전환, 자원 소모 및 정신력 점유를 독립적으로 연산하는 비즈니스 로직 계층입니다. 캐릭터 액터나 UI 위젯과 직접 결합하지 않고 데이터 패킷(`FMEODamagePacket`) 단위로 입출력을 처리하여 높은 재사용성과 테스트 용이성을 확보합니다.

## 2. 6단계 데미지 연산 파이프라인 (`UMEODamageSubsystem`)

`CalculateDamage(FMEODamagePacket InputPacket)` 호출 시 아래 6단계 파이프라인을 순차적으로 통과하며 최종 피해량을 산출합니다.

| **단계** | **파이프라인 모듈** | **연산 공식 및 처리 규칙** | **입출력 데이터 변화** |
| --- | --- | --- | --- |
| **Stage 1** | **기본 피해 합산** | • 무기/스킬 기본 피해(`BaseDamage`) + 플랫 추가 피해(`AddedFlatDamage`) 속성별 합산 | 5대 속성별 초기 피해 풀(`Stage1Pool`) 생성 |
| **Stage 2** | **속성 전환**

(`ApplyDamageConversion`) | • 무한 루프 방지를 위한 **단방향 전환 순서 고정**:

`Physical` $\rightarrow$`Lightning` $\rightarrow$ `Cold` $\rightarrow$`Fire` $\rightarrow$ `Chaos`
• 동일 소스 전환 합계가 100%(1.0) 초과 시 비율대로 자동 스케일 다운(정규화)하여 데미지 복사 버그 차단 | 전환된 수치는 목표 속성에 가산, 원본 속성 풀에서 차감 |
| **Stage 3** | **합연산 & 곱연산 증폭**

(`ApplyIncreasedAndMoreModifiers`) | • 공식: $\text{Converted} \times (1 + \sum \text{Increased}) \times \prod \text{More}$

• 합연산(`Increased`)과 보조 젬·키스톤 곱연산(`More`)을 분리 계산 | 속성별 증폭된 원시 피해 산출 |
| **Stage 4** | **명중 및 치명타 판정**

(`RollHitCheck`) | • 회피 가능 공격(`bCanBeEvaded`) 시 명중 확률 계산:

$\text{HitChance} = \text{Clamp}\left(\frac{\text{Accuracy}}{\text{Accuracy} + (\text{Evasion} \times 0.25)^{0.8}}, 0.05, 1.0\right)$

• 회피 성공 시 즉시 0 데미지 반환, 치명타 적중 시 전 속성 피해에 치명타 배율 곱연산 | `bIsEvaded`, `bIsCriticalHit` 플래그 확정 및 `MitigatedDamage` 초기값 기록 |
| **Stage 5** | **방어 기제 감쇄**

(`EvaluateMitigation`) | • **물리 피해:** 방어도 경감률 $\frac{\text{Armor}}{\text{Armor} + 5 \times \text{RawPhys}}$ 적용 (최대 90% 상한)

• **원소/카오스:** 유효 저항력 = $\text{Clamp}(\text{Min}(\text{Resist}, 0.75) - \text{Penetration}, -2.0, 0.75)$ 적용 | `MitigatedDamage` 내 5대 속성별 최종 실피해 확정 |
| **Stage 6** | **방어 풀 최종 배분**

(`DistributeFinalDamageToPools`) | • **물리·원소 피해:** 에너지 보호막(ES)이 우선 흡수하고 초과분(`Overflow`)만 생명력(Life)으로 전달

• **카오스 피해:** 에너지 보호막을 우회하여 생명력에 직격 | `FinalDamageToEnergyShield`, `FinalDamageToLife`, `TotalFinalDamage` 산출 |

## 3. 자원 소모 및 정신력(Spirit) 점유 관리 (`UMEOResourceSubsystem`)

스킬 1회 시전 시 소모되는 유동 자원(마나/생명력)과, 오라·지속 버프·소환수가 활성화되는 동안 최대치를 고정 점유하는 정신력(Spirit)을 분리하여 제어합니다.

| **관리 영역** | **핵심 함수** | **동작 메커니즘 및 검증 규칙** |
| --- | --- | --- |
| **소모량 산출** | `CalculateFinalResourceCost()` | • 공식: $\text{Round}\left(\text{BaseCost} \times \text{SupportCostMultiplier} \times (1.0 - \text{CostReductionPercent})\right)$

• 연결된 보조 젬의 배율 곱연산과 패시브 소모 감소율을 반영한 최종 정수 비용 반환 |
| **시전 자원 차감** | `ValidateAndConsumeCost()` | • `UPARAM(ref)` 참조 매개변수를 통해 보유 자원이 요구치 이상인지 검증 후 즉시 차감

• 자원 부족 시 `false`를 반환하여 스킬 시전 파이프라인 조기 차단 |
| **정신력 점유 등록** | `ReserveSpirit()` | • 동일 `ReservationId` 중복 점유 차단 및 잔여 정신력(`MaxSpiritPool - Reserved`) 부족 시 활성화 거절

• 통과 시 액터별 점유 목록(`ActiveSpiritReservations`)에 엔트리 등록 |
| **정신력 점유 해제** | `UnreserveSpirit()` | • 버프 비활성화 또는 소환수 소멸 시 해당 `ReservationId` 엔트리를 제거하고 점유량 즉시 반환

• 액터의 모든 점유 항목이 비워지면 맵 키(Key)까지 자동 정리하여 메모리 누수 방지 |

## 4. 핵심 엔지니어링 및 아키텍처 설계 포인트

- **패킷 기반 결합도 분리 (`FMEODamagePacket`):** 데미지 연산 결과를 단일 스칼라(`float`)로 뭉개지 않고 `MitigatedDamage` 구조체 내부에 5대 속성별 실피해를 개별 보존합니다. 이를 통해 후속 서브시스템(`UMEOAilmentSubsystem`)이 추가 재계산 없이 화염(점화), 냉기(동결), 번개(감전) 상태이상 축적치를 독립적으로 판정할 수 있습니다.
- **액터 수명주기 안전성 (`TWeakObjectPtr`):** `UMEOResourceSubsystem`이 월드 내 다수의 플레이어 및 소환수의 정신력 점유 상태를 추적할 때 일반 포인터 대신 `TWeakObjectPtr<AActor>`를 키로 사용하여, 액터가 갑자기 파괴되더라도 댕글링 포인터(Dangling Pointer) 크래시가 발생하지 않도록 설계했습니다.
- **책임 경계 명확화 (`PlayerState` vs `StatusComponent` vs `Subsystem`):**
    - `AMEOPlayerState`: 사망 시에도 유지되는 영구 데이터(레벨, 인벤토리, 패시브 노드) 보관
    - `UMEOStatusComponent` (Layer 3): 실시간으로 변동하는 현재 체력·마나·ES·정신력 수치 보유 (플레이어·몬스터 공용)
    - `UMEODamageSubsystem` / `UMEOResourceSubsystem` (Layer 2): 상태를 직접 소유하지 않고 순수 공식 검증 및 수치 변환만 수행하는 무상태(Stateless) 연산 엔진

## 추가 내용:

- **Q1. `UPARAM(ref)`는 무엇이고 원래 출력핀인가요?**
    - 언리얼 블루프린트 UHT 규칙상 `const`가 없는 일반 참조 매개변수(`float&`)는 기본적으로 노드 오른쪽의 출력 핀(Output Pin)으로 생성됩니다.
    - 여기에 `UPARAM(ref)`를 붙이면 *"새 값을 출력하지 말고, 외부 변수를 왼쪽 입력 핀(다이아몬드 모양 참조 핀)으로 받아서 원본 변수 값을 직접 수정하라"*는 지시가 됩니다.
- **Q2. 마나·생명력·ES는 `PlayerState`에 있는 게 아닌가요? `UMEOStatusComponent`와 역할이 겹치지 않나요?**
    - 전혀 겹치지 않으며 명확히 분리됩니다.
        - **`AMEOPlayerState`:** 레벨, 경험치, 인벤토리, 장착 장비, 찍은 패시브 노드 등 "캐릭터가 죽어도 유지되는 영구 데이터"만 보관합니다.
        - **`UMEOStatusComponent`:** 최대/현재 생명력, 마나, ES, 정신력, 초당 재생량 등 "실시간으로 깎이고 차오르는 전투 풀(Pool)"을 관리합니다. 몬스터는 `PlayerState`가 없지만 똑같이 체력·ES·저항을 가져야 하므로, 플레이어와 몬스터 모두 `UMEOStatusComponent`를 부착해 동일한 전투 파이프라인을 태웁니다. (현재 체력/마나 수치 자체는 서버에서 차감된 뒤 클라이언트 HUD 갱신을 위해 리플리케이션됩니다.)
- **Q3. `RemovedCount`는 어떻게 작동하고 지운 숫자를 알아서 무엇을 하나요?**
    - 주석에 스스로 추론하신 내용이 **100% 정확**합니다. `TArray::RemoveAll`은 조건식에 `true`가 나오는 원소를 전부 삭제한 뒤 삭제된 원소의 개수(`int32`)를 반환합니다. `return RemovedCount > 0;`은 "최소 1개 이상 찾아서 정상 해제했으면 `true`, 해당 ID가 없어서 아무것도 못 지웠으면 `false`를 반환하라"*는 C++ 관용 표현입니다.
    - 해당 코드 내용:
    
    ```jsx
    const int32 RemovedCount = Entries->RemoveAll([Reservationld](const FMEOSpiritReservationEntry& Entry)
    {
    return Entry.ReservationId == Reservationld;
    });
    ```
    
    - 해당 주석 내용:
    

- **Q4. `GeTotal()`로 합계를 보내버리면 화염/번개/냉기 피해를 각각 얼마 줬는지 어떻게 알아서 점화/감전/동결을 계산하나요?**
    
    ```
    //	모든 속성 피해 합계 반환
    float GeTotal() const
    {
    	return Physical + Fire + Cold + Lightning + Chaos;
    }
    ```
    
    - `GetTotal()`은 화면에 총 데미지 숫자를 띄우거나 총량을 확인할 때 쓰는 보조 함수일 뿐이고, 실제 파이프라인의 결과물인 **`FMEODamagePacket.MitigatedDamage` 안에는 `Physical`, `Fire`, `Cold`, `Lightning`, `Chaos` 수치가 끝까지 개별 분리되어 보존**됩니다.
    - 따라서 다음 단계에서 만들 `UMEOAilmentSubsystem`이 `FMEODamagePacket`을 넘겨받아 `MitigatedDamage.Fire`로 점화, `MitigatedDamage.Lightning`으로 감전, `MitigatedDamage.Cold`로 동결 축적치를 각각 독립 계산합니다.
- **Q5. 속성 전환 시("물리 100%를 화염으로 전환") 나머지 번개나 냉기 피해는 그대로 남나요? 일부만 전환할 수도 있나요?**
    - 네, 그대로 남으며 일부 비율 전환도 완벽히 동작합니다 (버그 ② 수정 기준).
    - 예를 들어 물리 100 + 냉기 30인 상태에서 `물리 -> 화염 50%` 규칙을 넣으면, 물리에서 50만 빠져 화염으로 가고 냉기 30은 건드리지 않으므로 최종적으로 **물리 50 + 화염 50 + 냉기 30**이 됩니다.
    
    ```jsx
    for (const FMEODamageConversionRule& Rule : ValidRules)
    {
        const float EffectiveRatio = Rule.ConversionRation * ScaleFactor;
        const float ConvertedAmount = SourceAmount * EffectiveRatio;
    
        // 1. 목표 속성에 전환된 데미지 누적
        ResultPool.SetByType(Rule.TargetType, ResultPool.GetByType(Rule.TargetType) + ConvertedAmount);
        TotalConvertedOut += ConvertedAmount;
    }
    
    // 2. 루프 종료 후 전환된 총량만큼 원본 속성 풀에서 차감
    ResultPool.SetByType(SourceType, FMath::Max(0.0f, SourceAmount - TotalConvertedOut));
    ```
    
- **Q6. `EvaluateMitigation`에서 `DamagePacket`에 다시 대입한 코드가 없는데 왜 반영되나요?**
    - 역시 주석에서 정확히 짚으신 대로 `FMEODamagePool& DmgPool = DamagePacket.MitigatedDamage;`에서 `&` (참조, Reference)로 받았기 때문입니다. 복사본이 아니라 `DamagePacket.MitigatedDamage`의 메모리 주소를 직접 가리키고 있으므로 `DmgPool.Fire` 등을 수정하면 원본 패킷 내부 값이 즉시 바뀝니다.

```jsx
    const FMEOCombatStatSnapshot& Stats = DamagePacket.StatSnapShot;
    FMEODamagePool& DmgPool = DamagePacket.MitigatedDamage;
```
